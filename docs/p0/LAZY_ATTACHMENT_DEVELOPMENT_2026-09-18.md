# 惰性挂接与独立果梗支撑：开发记录

本轮基于 `9d5fefc`，针对接触抓取与 DART 挂接拓扑进行修复。它不是多果资格批次或正式验收；开发场景仍使用种子 45504，未消费隐藏种子或正式 claim。

## 已实现的行为

- 新增 `strawberry_gazebo_plugins`：夹爪挂接默认不创建约束，只在请求后创建；果实仍有其他输入挂接时不创建第二条约束。子模型缺失或名称不唯一时不确认就绪。
- `gripper_attachment_backend:=lazy` 为显式开发选项；默认仍为 `upstream`，保留历史固定场景行为。
- 广义 lazy 场景使用独立、无几何、固定到世界的果梗支撑，不再把果实固定到机械臂底座。原始 world 不覆盖，launch 写出新的物化 world。
- 双指接触门通过后，先释放果梗并确认，再请求夹爪挂接。失败时取消包括尚未完成的挂接请求，不把果实重新固定到未验证的位置。
- 上述确认要求收到请求之后的新状态，不能用已有的 `detached` 值立即确认。本机制不是跨话题请求序号协议，不能声称消除了所有传输乱序问题。
- 只读 ECM 观察器新增 GRAPH 记录，包括暂停插入阶段的双输入约束计数。它不是物理焊接、碰撞安全或采摘成功证明。

未改控制器、成熟度、不确定度、腕部修正距离、关节限位、碰撞、接触和重试安全阈值；未启用整臂自碰撞。实测源文件中的位置控制比例增益为 **1.5**，本轮保持不变；历史记录中的 1.0 描述不应当作为本轮配置依据。

## 为什么这样修改

旧代码的夹爪挂接和果梗挂接都从插入时 attached 开始；运行时换手也曾先夹爪挂接、再果梗释放。ECM 启动观测确实出现五颗果实各两条输入挂接，修正后未观察到该状态。但暂停 ECM 中的存在不证明 Physics 实际处理过闭环，不能据此宣称已确定历史 joint5 失败根因。

果梗固定到机器人底座还可能令果实与手指属于同一物理树，从而影响自碰撞过滤。独立支撑用于隔离这一因素，不通过开启整臂自碰撞或取消双指接触门来绕过问题。

Gazebo 文档要求 DetachableJoint 拓扑为树，并提示 DART 的接触重挂接限制：
[官方说明](https://gazebosim.org/api/sim/8/detachablejoints.html)，
[gz-sim8 实现](https://github.com/gazebosim/gz-sim/blob/gz-sim8/src/systems/detachable_joint/DetachableJoint.cc)。
新插件使用公开 ECM 协议；`attached` 表示组件状态转换，仍须通过果实随动、释放和入箱证据验证物理结果。

## 已完成验证

- 879 项纯 Python 测试，0 失败、0 错误、3 跳过。
- 本轮重跑 Gazebo 插件、仿真、操作、bringup 四个包；汇总缓存结果为 752 项、0 错误、0 失败。不是全部 ROS 包本轮重跑。
- C++ 挂接策略测试通过。
- 启动 smoke：旧 upstream 的 GRAPH 为 10 条挂接、5 个双支撑子链接；惰性挂接版本为 5 条、0 个双支撑。独立果梗支撑版本启动并恢复仿真，清理码 0。
- 第一轮完整开发运行（v1，惰性夹爪但仍使用机器人底座果梗）两次未获得果实接触，未进入换手或搬运验证，harvested=0。此运行不能验证后加的独立支撑或新状态确认。
- 第二轮（v2，DART、独立果梗）获得真实双指接触，CONTACT_RESOLVED 对应 fruit entity 1；果梗到夹爪换手时 GRAPH 为 5→4→5，双支撑计数均 0。撤离与搬运走廊完成，但箱口对准仍 joint5 容差中止，恢复回零仍失败，终态 `RECOVERY_HOME_FAILED`、harvested=0、清理 CLEAN。没有入箱通过证据。
- v2 的 `57.685 s`，实际速度约 `+0.527 rad/s`，进入 Physics 的速度命令却是 `-1.714 rad/s`；`57.735 s` 命令为 `-11.264 rad/s` 而实际仍 `+0.509 rad/s`。回零 `60.91 s` 命令为 `+12.333 rad/s` 而实际 `-0.041 rad/s`。这再次不支持这些窗口的“旧负速度命令卡住”解释；精确物理根因仍未定。
- 独立支撑解决了该场景本次运行的接触确认，不等于已证明解决所有随机场景的接触问题，也没有修好上述关节异常。
- 第三轮（v3，同一行为代码、Bullet Featherstone）两次检测为 RIGHT_SINGLE_FRUIT，均拒绝挂接；600.084 秒 HARD_TIMEOUT，未收到批次终态、harvested=0，清理 CLEAN。没有路径容差中止，但也没有完成带果运动，因此不能用此结果证明 Bullet 修好带果对准。评分仍 FAIL/INDETERMINATE，不推广引擎或后端。

## 推广门

在真实双指接触、物理随动、释放、入箱和回零完成之前，不将 lazy 推广为默认后端，不宣称单果或多果开发门通过。无路径容差中止也不能单独证明历史控制故障被修好。

下一步应对已复现的 DART 挂接后关节运动做最小物理复现，检查引擎关节句柄/约束处理，而不是继续提高增益或重放旧路径；Bullet 则须先解决有测量依据的单侧接触，才有资格比较带果运动。不得跳过接触确认来制造成功。
