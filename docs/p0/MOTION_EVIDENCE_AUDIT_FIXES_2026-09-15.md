# 轨迹、时间戳与独立停止证据修复

## 当前结论

本轮完成了机械臂运动证据链和停稳判定的工程加固。结果仍属于开发/工程验证，不构成 G1 运动放行、正式泛化验收或多果采摘成功证明。

## 修复范围

1. **期望/实际轨迹**
   - 记录直接 `FollowJointTrajectory` 命令和 MoveIt 执行轨迹的完整关节名、waypoint、速度字段和 `time_from_start`。
   - 记录控制器 Jazzy `reference`、`feedback`、`error` 原始数组。
   - 按关节名对齐并计算 `computed_error_rad`，不按诊断日志下标猜测物理关节。

2. **双时钟采样**
   - `/joint_states` 保留消息头 ROS 采集时间、记录器接收时的 monotonic 时间和记录器 ROS 当前时间。
   - 重复、回退、未来、过期、断流、维度错误和非有限位置/速度均显式记录，不能静默跳过。

3. **独立停止证据**
   - 停止判断只使用独立订阅的完整 Panda 七关节位置/速度窗口，不使用控制器成功布尔值或缓存 planning scene 状态替代。
   - 采集时间和接收时间都必须新鲜；位置稳定、速度上限、连续时长和样本数量同时满足。
   - “已停止”和“已回到 home”分开判定。
   - 后端停稳门按设计只校验完整七关节**位置**（缺失速度的采样仍可进入位置稳定判定）；独立 `StopEvidence` 才额外要求速度完整、有限并在限值内。两者证据用途不同，不互相替代。

4. **P1/P2 缺陷修复**
   - 完整手臂位置、序列号、采集时间和接收时间作为同一不可拆分快照原子更新；指关节局部消息或格式异常的七关节消息不能覆盖完整手臂反馈。
   - 轨迹结果等待明确区分控制器终态、独立关节限位中止、结果 future 异常和墙钟超时，不再把不同失败统一记录为超时。
   - `ACTION_*` 事件必须能关联同一生产者、身份有效且时序更早的 `COMMAND_PREPARED`；无效事件不能污染后续序号/准备状态，重复 `command_id` 不能重绑定所有者。
   - `NaN`、`Inf` 和 `1e309` 等异常事件不使记录器崩溃；异常载荷保留为诊断表示并标记问题。

## 验证

- 停稳门对抗测试：16/16 通过。
- 遥测记录器测试：17/17 通过。
- 运动证据路径测试：9/9 通过。
- manipulation 分包 pytest：222 项通过。
- bringup 分包 pytest：145 项通过。
- 纯 Python 全量测试：840 项通过，0 错误、0 失败。
- manipulation 与 bringup 两个 ROS 包构建成功。构建保留既有 setuptools `tests_require` 警告，不描述为零警告。
- 真实静止 ROS 采样已完成：原始采样文件保持不变，离线重放可得到独立停止窗口；采样中的重复时间戳仍作为覆盖问题保留。

以上测试入口存在重叠，不能相加为独立测试总数。

## 明确限制

- 未证明 v7 的 `panda_joint7` 控制器跟踪超差已经解决。
- 未证明夹取后回放置路径发生碰撞；当前旧 v7 证据在放置验证前因控制器跟踪超差终止。
- 未提供完整碰撞对象、关节限位、附着终态和场景终态的独立全区间证据。
- 未启动正式 30 种子矩阵，也未访问封存的 115 张真实测试集。
- 当前工作树改动在本报告形成时尚未提交；运行证据必须另行绑定提交/源码/安装包哈希后才能作为正式结果使用。

## 参数边界

本轮没有调整 `panda_joint7` 速度、控制器路径容差、正式场景、正式矩阵或封存测试集。后续若要针对跟踪超差做单变量实验，必须先绑定命令轨迹、实际反馈和两个时钟，再根据轨迹证据选择变量。
